깨진 `.twb/.twbx` 1개를 입력으로 받아 **결함 1층**을 규칙으로 바꾸는 루프 1회분이다.
이전 반복의 기억은 없다고 가정한다 — 상태는 저장소에서 읽는다.

`/impl-loop`과 역할이 다르다:

| | 입력 | 산출 |
|---|---|---|
| `/impl-loop` | 계획서(`07` §4) | 계획된 작업 단위 1개 |
| `/defect-loop` | **Tableau가 거부·경고한 실파일** | 규칙 1개 + 주입 레시피 1개 |

핵심 전제 — **결함은 층으로 쌓여 있다.** 한 층을 고치면 Tableau가 다음 층을 보여준다.
2026-07-30 MA_003 매출표 한 파일이 3층을 냈다 (05 F5-b·F5-c·F5-d·F5-e):
로드 거부 → 설정이 버려짐 → 데이터가 안 나옴. **한 반복에 한 층만 한다.**

## 0. 상태 파악 (생략 금지)

1. `docs/impl-progress.md` · `docs/07-implementation-guide.md` §1(G1~G10)을 읽는다
2. `git log --oneline -5`
3. 골든셋을 걸고 baseline 게이트를 돌린다. **환경변수와 명령을 한 호출에 둔다** —
   Bash 도구는 셸 상태를 유지하지 않아 따로 `export`하면 조용히 skip된다:

```bash
export TWB_LINT_GOLDEN_NORMAL='C:/dev/JW/2.개발/MA_00*/*.twbx' \
  && .venv/Scripts/python -m pytest -q \
  && .venv/Scripts/python -m ruff check .
```

baseline이 red면 새 작업을 시작하지 않는다. 그 red가 이번 반복의 작업이다.
(mypy는 이 머신에서 실행이 차단돼 있다 — CLAUDE.md 참조)

## 1. 증상을 고정한다

사용자가 준 오류 문구를 **그대로** 적어 둔다. 번역·요약하지 않는다 — 나중에 정상본
대조의 검색어가 되고, 레시피의 `expected`가 된다.

그다음 린터를 그 파일에 돌린다:

```bash
.venv/Scripts/python -X utf8 -c "
from twb_lint.validation.engine import validate
r = validate(r'<경로>')
print(len(r.findings))
for f in r.findings[:20]: print(f.severity.name, f.rule_id, f.line, f.message[:100])"
```

- **린터가 이미 잡았다** → 규칙은 있다. 사용자에게 고침 방법만 주고 루프를 끝낸다
- **0 findings인데 Tableau는 거부한다** → AC3 위반이다. 이번 반복의 재료다

## 2. 정상본과 대조한다 — 여기서 답이 나온다

**추측하지 않는다.** 같은 기능을 쓰는 정상 파일이 어떻게 직렬화하는지 세어 본다.
2026-07-30의 5층이 전부 이 한 단계에서 풀렸다.

```python
# 스크래치패드에 두고 돌린다. 저장소에 남기지 않는다.
import glob, io, zipfile
from lxml import etree
paths = glob.glob(r'C:\dev\JW\**\*.twb', recursive=True) + \
        glob.glob(r'C:\dev\JW\**\*.twbx', recursive=True)
# 각 파일에서 문제 요소/속성을 뽑아 모양별로 센다
```

세는 것:

1. **그 요소를 쓰는 정상본이 몇 개인가** — 0개면 표본이 없다. 규칙화하지 않는다
2. **정상본의 모양은 몇 가지인가** — 1가지면 강한 불변식이다
3. **깨진 파일만 다른 모양인가** — 반례 0이어야 규칙이 된다

판정 기준: **불변식 N건 : 반례 0건** (2026-07-30 실측은 714:0, 3377:0, 22:0이었다).
반례가 하나라도 있으면 그 반례를 먼저 이해한다. 이해 못 하면 규칙화하지 않는다.

**매니페스트를 먼저 의심한다.** 로드 거부(D2E8DA72)에 `no declaration found for
element 'X'`가 있으면 십중팔구 XSD가 아니라 게이트다 — `<document-format-change-manifest>`
항목 집합을 정상본과 diff 한다 (05 F5). XSD는 그 요소를 무조건 허용한다.

## 3. 최소 수정본을 만들어 사용자에게 준다

**한 층만 고친다.** 두 층을 같이 고치면 어느 쪽이 증상을 없앴는지 모른다.

- 스크래치패드에 `<원본>_fixed_vN.twb`로 낸다. 원본을 덮어쓰지 않는다
- **문자열 치환 금지** — `twb.parse()` → 트리 조작 → `twb.serialize()` (02 S1-1)
- 만든 뒤 린터를 다시 돌려 0 findings인지 본다
- 사용자에게 **절대경로**를 준다. Tableau가 그 파일을 이미 열고 있으면 닫기를 기다리지 않는다 —
  다른 이름(`<원본>_fixed_vN+1.twb`)으로 새로 만들어 그 경로를 준다

사용자가 "열린다/데이터 나온다"를 확인해 주기 전에는 규칙화하지 않는다.
확인 없이 만든 규칙은 우리 추측을 남의 파일에 강제하는 것이다.

## 4. 규칙으로 옮긴다

`validation/semantic/` 파일 1개 + `@register`. 코어(`engine.py`·`registry.py`) 무수정.

- **심각도**: 파일이 안 열린다고 확신할 때만 ERROR. 열리는데 설정만 버려지면 WARNING
  (02 S1-6). 오늘까지 ERROR는 매니페스트 게이트·XSD·규칙 ③⑭⑮⑰뿐이다
- **모르면 침묵**: 판정에 필요한 정보를 못 얻었으면 위반이 아니라 `note_partial`이다.
  판정 불가와 위반을 섞으면 우리 지식의 공백이 남의 정상 파일을 막는다
- **모양을 열거하지 말고 성질을 본다**: "속성이 A거나 B여야 한다"보다
  "기반 필드가 있어야 한다"가 낫다. 릴리스가 바뀌면 모양은 늘고 성질은 남는다
- 근거를 독스트링에 **숫자로** 적는다: `정상본 714건 : 반례 0건`. 나중에 이 규칙을
  의심할 사람에게 필요한 것은 결론이 아니라 표본 수다

단위 테스트는 `tests/fixtures`의 `make_twb()`/`make_ctx()`로. 최소 4개:
위반 1 · 정상 1 · **거짓양성 함정 1**(비슷하지만 정상인 모양) · 입력 없음(skip 보고).

## 5. 주입 레시피를 추가한다

`tools/inject_defects.py`에 `Recipe` 1건. 정상본에서 그 층을 **되돌리는** 변형이다.

```bash
.venv/Scripts/python tools/inject_defects.py --source <정상본> --out <스크래치패드>/injected
```

`tests/golden/test_injection.py::test_every_recipe_is_caught_by_the_rule_it_declares`가
레시피 목록 자체를 입력으로 삼는다 — 레시피를 넣으면 검사는 자동으로 따라온다.

## 6. 회귀 — 통과 못 하면 커밋하지 않는다

```bash
export TWB_LINT_GOLDEN_NORMAL='C:/dev/JW/2.개발/MA_00*/*.twbx' \
  && .venv/Scripts/python -m pytest -q && .venv/Scripts/python -m ruff check .
```

추가로 **실파일 전수 회귀**를 돌린다 (스크래치패드 스크립트, 61개 기준):

- 정상본 ERROR **0** (AC7) — 여기서 깨지면 파일이 아니라 규칙을 의심한다
- 새 규칙의 finding이 **깨진 파일에서만** 난다. 정상본에서 1건이라도 나면 규칙이 틀렸다
- 새 규칙이 낸 WARNING 건수를 대장에 적는다 (경고 인플레이션 감시)

## 7. 커밋 + 문서

- `docs/05-xsd-spike.md`에 실측 소절(F5-x)을 추가한다 — **오류 원문 · 대조 수치 · 표본 수**
- `docs/06-rule-candidates.md`에 후보 항목(R번호)을 추가하고 "구현됨 = rule ⑨"로 표시
- `docs/impl-progress.md` 반복 로그에 한 줄 (게이트 수치 포함)
- 커밋 본문에 **왜**를 적는다. 특히 "규칙 ②/⑦가 왜 이걸 못 잡았나"를 적는다 —
  못 잡은 이유가 다음 규칙의 설계 근거다

## 8. 다음 층으로

사용자가 고침본을 열어 새 증상을 보고하면 **1번으로 돌아간다.** 새 증상이 없으면
그 파일은 끝난 것이다 — 그때 그 파일을 골든셋 정상본에 추가하는 것을 제안한다
(사용자 확인이 있었으므로 라벨 신뢰성이 확보돼 있다).

## 멈춤 조건

- 정상본 표본이 0개다 → 규칙화하지 않는다. "표본 없음"을 대장에 남기고 끝낸다
- 반례가 있고 이해되지 않는다 → 규칙화하지 않는다. 관측을 문서에만 남긴다
- 같은 실패로 3회 연속 막혔다 → 멈추고 시도한 것과 정확한 오류 문구를 보고한다
- 증상이 **데이터 값에 달렸다**(숫자가 틀리다, 결과가 비었다) → 오프라인 게이트의
  범위 밖이다. 그렇게 말하고 끝낸다. 파일만 보고 판정할 수 없는 것을 추측하지 않는다

## 절대 하지 않는 것

- 사용자 원본을 덮어쓰지 않는다. 산출은 스크래치패드에
- 정상본 표본 없이 규칙을 만들지 않는다 (추측 ERROR = AC7 붕괴)
- 한 반복에 두 층을 고치지 않는다
- 게이트가 red인데 커밋하지 않는다. 단언을 약화시켜 통과시키지 않는다
- 저장소에 실파일을 남기지 않는다 — 골든셋은 사내 재무 데이터다
