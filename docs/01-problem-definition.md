## 1. 문제 (한 문장)

> **AI가 만들거나 고친 `.twb/.twbx`를 Tableau에서 열었을 때, 화면에 빨간 느낌표가
> 하나도 없어야 한다.** 그것을 Tableau를 실행하지 않고 판정한다.

"열린다"가 아니라 **"열리고 제대로 뜬다"**가 기준선이다. 이 차이가 v1.2 → v2.0의 전부다.

## 2. 관측 — 무엇은 안전하고 무엇이 위험한가

사용자 실사용 기준(2026-07-31):

| 작업 | 위험도 | 왜 |
|---|---|---|
| **기존 파일의 일부 수정** (계산필드 수식·로직 변경) | 낮음 | 구조가 이미 서 있다. 값만 바꾸므로 참조·매니페스트·선반이 그대로다 |
| **새 파일 생성** | **높음** | 모든 구조를 처음부터 세워야 한다. 매니페스트·window·viewpoint 등 "보이지 않는 배선"이 빠진다 |
| **집합·동작 추가** | **높음** | 새 요소가 매니페스트 게이트를 건드리고, 시트·필드 양쪽을 참조한다 |
| **선반 배치 변경** (페이지·필터·마크·열·행) | **높음** | 배치가 새 참조 표기를 만들고, 필드 성질(차원/측정·집계)과 선반이 맞아야 한다 |

**즉 문제는 "편집"이 아니라 "생성"에 있다.** 검증기의 무게중심이 여기로 옮겨간다.

## 3. 실패는 층으로 나온다 (실측)

실사용 파일 1개가 **4층**을 냈다. 앞 층을 고치기 전에는 뒤 층이 **보이지 않는다** —
Tableau가 첫 실패에서 멈추기 때문이다 (근거: [`05-xsd-spike.md`](./05-xsd-spike.md) F5-b~F5-e).

| 층 | 증상 | 사용자가 보는 것 |
|---|---|---|
| 1 | 로드 거부 (`D2E8DA72`) | 파일이 안 열린다 |
| 2 | 설정이 버려짐 | 열리는데 **필터가 사라졌다** — 조용히 틀린 숫자 |
| 3 | 계산 오류 상태 | 열리는데 **데이터가 하나도 안 나온다** |
| 4 | 필드·집합 오류 상태 | 열리는데 **빨간 느낌표** |

**층 1만 막는 게이트는 쓸모가 절반이다.** 2~4층은 파일이 "열리므로" 통과로 기록되지만,
사용자에게는 실패다. v1.2의 성공 기준(`§5 무에러 보장`)이 층 1에 치우쳐 있었다.

**함의 — 한 반복에 한 층만 고친다.** 그 절차가 [`/defect-loop`](../.claude/commands/defect-loop.md)다.

## 4. 판정 대상 4항목 (T1~T4)

§3이 *증상*의 축이라면, 여기는 *표면*의 축이다. 규칙은 표면별로 붙는다.

### T1. 파일이 무조건 열린다

XML well-formed + 공식 XSD + **매니페스트 게이트** + named-content 3자 일치.
= 층 1 전체. **현재 가동 중이다** (규칙 `xsd.schema`·`named.refs`·`manifest.gates`).

⚠️ XSD 통과 ≠ 열린다. 유효 문법 = `version` 선언 × `<document-format-change-manifest>`
항목 집합이며, **공식 XSD는 이 축을 원리적으로 못 본다** (부록 A §8.1).

### T2. 계산필드·매개변수가 오류를 내지 않는다

- 함수명이 그 릴리스에 실존하는가 (`calc.functions`)
- 참조하는 필드가 실존하는가 (`calc.field_refs`)
- 매개변수를 **`[Parameters].[이름]`으로 한정**했는가 (`ref.notation` ⑦-c)
  — 한정 없으면 계산이 통째로 깨지고 **데이터가 안 나온다** (층 3)
- `derivation="User"`로 올린 계산의 수식에 집계가 있는가 (`calc.aggregation`)
- **미구현**: 타입 정합(문자열↔숫자) · 집계와 비집계 인자 혼합 · `IF` 분기 반환형

### T3. 집합·동작을 걸어도 오류가 나지 않는다

- 집합에 **기반 필드가 있는가** (`set.definition`) — 없으면 그 집합을 쓰는 계산이 전부 깨진다
- **동작(`<actions>`) 배선** (`action.refs`, 2026-07-31) — 소스 시트·대시보드·데이터소스 ·
  제외 시트 · 대상 매개변수(실존 + `[Parameters]` 한정자) · 대상 집합 · 원본 필드.
  표면 9종을 실파일 84개 전수 실측으로 확정했다 (06 R17)

### T4. 페이지·필터·마크·열·행에 올려도 오류가 나지 않는다

두 갈래로 나뉘고 난이도가 다르다:

| | 무엇 | 정답지 | 상태 |
|---|---|---|---|
| **T4-a 참조 무결성** | 선반 위 참조가 실존하고 표기가 맞는가 | **있다** — 실파일 84개 | ✅ `shelf.refs` (06 R18) |
| **T4-b 조합 규칙** | 어떤 필드를 어떤 선반에 놓으면 오류인가 | **없다** | ⏸ §7 |

T4-a는 행·열(요소 텍스트, 수식 가능) · 페이지 · 필터 · 마크 · 정렬 · 축·참조선을 본다.
**T4-b는 §7의 열린 질문이다.**

## 5. 성공 기준

- **빨간 느낌표 0** — 산출물을 Tableau에서 열었을 때 층 1~4 중 어느 것도 나타나지 않는다
- **오프라인·결정론적** — Tableau를 실행하지 않고 판정한다. 같은 입력 → 같은 판정
- **거짓양성 0을 ERROR에서 지킨다** — 정상 실파일에서 ERROR가 1건이라도 나면 게이트가
  무력화된다. 확신 없으면 WARNING이다 ([`02-specification.md`](./02-specification.md) S1-6)
- **검사 못 한 것을 말한다** — 침묵을 "통과"로 읽히게 두지 않는다 (`coverage`)

### 검증 비용

느린 E2E(Tableau 실행→스크린샷) 의존을 오프라인 검증으로 대체하는 것이 실용성의 핵심.
E2E는 제거가 아니라 **최종 1회 게이트로 격하**한다 — render 런타임(빈 viz 등)은 여전히
정적으로 못 잡는다 (부록 A §8).

## 6. 비-목표

- Cloud/Server REST API 연동 — 공식 `Validate Workbook`이 있으나 **Cloud 전용**이고
  사용자 환경은 로컬 오프라인이다 (부록 A §2.1)
- 실시간·고빈도 데이터 스트리밍
- render 정확성(레이아웃이 예쁜가·숫자가 맞는가) — 오류 유무만 본다
- 자동 수정(auto-fix) — 판정이 먼저다. 수정은 판정이 신뢰를 얻은 뒤

## 7. 열린 질문

- **T4-b 조합 규칙의 정답지가 없다.** 어떤 필드×선반 조합이 빨간 느낌표를 내는지는
  XSD에도 매니페스트에도 적혀 있지 않다. 실파일 관측(정상본 61개에서 나타나는 조합만
  정상)으로 근사할 수 있으나, 그것은 "본 적 없는 조합 = 오류"라는 거짓양성 기계다.
  → **Tableau에서 조합을 열어 보는 배치가 필요하다** (`TODO.md` L1)
- **심각도 승격 대기 2건** — `manifest.gates` ⑥-a, `calc.field_refs` 표면별.
  라벨 없이는 WARNING으로 **동결한다** (`TODO.md` L2)
- **`version` 역산 규칙** — 편집이 새 기능 요소를 넣으면 매니페스트 항목과
  `<workbook version>`을 함께 올려야 하는데, 어느 항목이 어느 최소 버전을 요구하는지 모른다.
  read-only에는 무해하나 **생성·편집에서 터진다**.
  `version`이 "사용 기능들로부터 역산된다"([`05-xsd-spike.md`](./05-xsd-spike.md) F4)는
  관측이 단서다 — 역산 규칙을 알면 생성기가 스스로 계산할 수 있다
- **정상 표본의 다양성** — 실파일 61개지만 워크북 원본 종수는 그보다 훨씬 적다.
  "ERROR 0건"은 표본 다양성만큼만 강하다
- **live DB connection** — 오프라인 검증 불가 영역. 경고로만 낸다 (설계 D6)

# 부록 A — v1.2 본문 (조사·실측 근거)

> 아래는 2026-07-29까지의 문제정의 본문이다. **§1~§7이 이를 대체하지만, 근거는 여기 있다.**
> 시장 조사·근본 원인 분석·XSD 실측·시맨틱 커버리지 매핑은 여전히 유효하다.

## A.1 배경

Tableau에는 로컬 `.twb/.twbx` 파일을 **저작·편집**해주는 신뢰 가능한 AI가 없다. 현재 AI에 Tableau 파일 작업을 맡기면 자주 파일이 깨지거나 틀린 결과가 나온다.

## A.2 현황 분석 (2026-07)

| 구분 | 대상 | 능력 | 빈틈 |
|---|---|---|---|
| 공식 `tableau/tableau-mcp` | Cloud/Server API | 데이터 쿼리·콘텐츠 탐색·뷰 렌더 (**읽기**) | 워크북 생성/편집 없음, 쓰기 없음 |
| Tableau Agent(Einstein) | Cloud 세션 | 시트 단위 대화형 탐색 | 대시보드 빌드·데이터모델링 불가, 시트간 인식 없음, **버전관리용 독립 파일 생성 안 됨**, 오프라인·무인 자동화 불가 |
| 커뮤니티 MCP (Loki, hetpatel, wjsutton 등) | 주로 REST API | 쿼리·관리·CSV 추출 | 로컬 파일 저작 도구 없음 |

**결론: 로컬 `.twb/.twbx`를 에러 없이 저작·편집하는 도구는 시장에 없다.**

### A.2.1 공식 검증 REST API (2026-07-28 확인)

공식 XSD 레포 README에 명시:

> Tableau Cloud June 2026 / Server 2026.2부터 REST API로 **구문·시맨틱 양쪽** 검증 가능
> (`Validate Workbook`, `Validate Workbook and Upload`).
> *"Semantic validation: Successful semantic validation means that a workbook will open in Tableau."*

공식이 시맨틱 검증 능력을 갖췄다. 다만 **Cloud/Server 온라인 전용**이다.

- 이 프로젝트 요구는 **로컬·오프라인** → 대체재가 아니다
- 사용자 환경은 **로컬 전용, Cloud 접근 불가**(2026-07-28 확인) → 이용 불가
- 골든셋 라벨링 오라클로 쓸 여지도 같은 이유로 없음 → **라벨링은 로컬 Tableau Desktop 2026.1 수동**

## A.3 근본 원인

### A.3.1 "2계층 유효성" 문제

- **(A) 구문 유효성** — XML well-formed. 파서로 쉽게 검증. **통과해도 안 열리는 경우가 대부분.**
- **(B) 시맨틱 유효성** — Tableau 내부 스키마 + 참조 + 메타/데이터 일관성. **여기서 깨지면 XML 검증 통과해도 로드 실패.**

### A.3.2 (B) 시맨틱 실패 유형

1. **스키마/속성 오류** — well-formed지만 Tableau 스키마 위반 → 로드 실패
2. **참조 무결성 붕괴** — 필드 rename/삭제 후 참조 미갱신 → dangling reference
3. **ID/이름 링크 불일치** — worksheet↔dashboard, window↔view 연결 어긋남
4. **버전 속성 불일치** — `<workbook version=...>`와 실제 사용 기능 불일치
5. **메타↔데이터 불일치** — `.twb` 필드 참조와 `.hyper` 스키마 어긋남 → 열려도 렌더 실패
6. **LLM 환각 문법** — 지원 안 되는 calc field 문법 생성

### A.3.3 부가 원인

- **도메인 지식 부재** — 스키마·문법·구조를 AI가 정확히 모름
- **문자열 편집** — AI가 XML을 문자열로 조작 (공식 결론: 수동 XML 편집은 최후수단, 극도로 error-prone)

### A.3.4 검증 비용 (사용자 실측)

현재 유일하게 믿을 만한 (B) 검증 = **Tableau를 직접 실행→스크린샷→확인하는 E2E**.
정확하지만 매 편집마다 앱 기동·렌더 비용. → 빠른 결정론적 검증이 이를 대체해야 실용적.

## A.4 공식 스키마 조사 (2026-07)

**Tableau가 2026-02 공식 XSD 공개** — `tableau/tableau-document-schemas`.

- **커버 (=A 구문)**: 버전별 `twb_2026.1.0.xsd` 등. 표준 XML 검증기로 오프라인 적용 가능
- **명시적 非커버 (=B 시맨틱, 리포가 직접 경고)**:
  1. connection element 속성
  2. **calc field 내용 (함수명·객체 참조)**
  3. **named workbook content 참조 (탭 이름 등)**
  4. `processContents="skip"` 로 표시된 요소
- **`.twbx`(패키지)는 스키마 미지원** — unpack 후 `.twb`만 검증 가능

> **(A) 구문 검증 = 공식 XSD로 오프라인 해결됨 (재발명 불필요).**
> **(B) 시맨틱 검증 = 공식이 명시적으로 안 하는 영역. → 이 프로젝트가 만들 빈틈.**

메타↔hyper 대조는 `tableauhyperapi`의 `Catalog.get_table_definition()`으로 오프라인 가능.

### A.4.1 실측 (2026-07-28) — 공식 XSD를 그대로는 쓸 수 없다

실사용 워크북 9개로 실제로 돌려본 결과 ([`05-xsd-spike.md`](./05-xsd-spike.md)):

> **정상 파일 9개 전부가 공식 XSD를 통과하지 못한다.** 전처리 3단계를 넣어야 9/9 통과한다.

| 결함 | 내용 | 대응 |
|---|---|---|
| XSD 컴파일 불가 | `user`·`xml` 네임스페이스를 `schemaLocation` 없이 import | 스텁 스키마 2개 주입 |
| `_.fcp.` 미모델링 | 하위호환 접두사(`_.fcp.<기능>.true...<이름>`)를 XSD가 모름 → 파일당 48~55건 | 검증 전 접두사 정규화 |
| 과엄격 | `explain-data`가 필수인데 실제 Tableau는 미사용 시 안 씀 | XSD 패치(`minOccurs="0"`) |

**vendoring이 원본 복사가 아니라 패치 파이프라인이 된다.**

부수 확인 — `<workbook version>`은 저작 버전이 아니다. 2026.1이 만든 파일도
`version='18.1'`(= 최소 호환 버전)로 저장된다. 버전↔XSD 매핑은 **`source-build`** 기준이다.

## A.5 시맨틱 커버리지 매핑 (E2E 완전제거 가능한가?)

Tableau **자체 linter는 없다** — 커뮤니티 도구 BMB·python calc 추출기만 존재.

| 항목 | 오프라인 잡힘 | 방법 |
|---|---|---|
| calc 함수명·객체 참조 | **높음** | calc 스캐너 + 버전별 함수 화이트리스트 + 필드 참조 그래프 |
| named content 참조(탭·window) | **높음** | 트리 순회로 참조명 존재 검사 |
| 메타↔hyper 불일치(embedded) | **높음** | `hyperapi Catalog`로 hyper 스키마 vs `.twb` 필드 대조 |
| connection 속성 | **중간** | 필수속성·타입 정적검사 O / live DB 실제연결 X |
| `processContents="skip"` 요소 | **낮음** | 구조적으로 불투명(벤더확장/동적) |
| **매니페스트 미선언 기능** | **높음** | 기능↔매니페스트 항목 대응표 대조 — **XSD가 원리적으로 못 잡는 영역** |
| **render 런타임** (blank viz, device layout) | **불가** | 실제 쿼리실행·마크렌더 필요 — **E2E 전용 잔여영역** |

### A.5.1 로더 문법 ≠ XSD 문법 (2026-07-28 실측)

> **유효 문법 = `version` 선언 × `<document-format-change-manifest>` 항목 집합.**
> 기능을 쓰면서 대응 매니페스트 항목을 선언하지 않으면
> `no declaration found for element '<요소>'`로 **로드 거부**된다.

실측 쌍: `<manual-sort>` ↔ `SortTagCleanup`, `<edit-group-action>` ↔ `GroupAction`+`GroupActionAddRemove`.

**공식 XSD는 `manual-sort`를 무조건 허용한다.** 즉 매니페스트 없이 쓴 파일은
(A) 구문 검증을 통과하고 Tableau에서 열리지 않는다.
→ L-B 규칙으로 편입 ([`06-rule-candidates.md`](./06-rule-candidates.md) R1).

### A.5.2 결론: E2E 완전제거는 불가, 격하는 가능

> 로드-실패 클래스는 대부분 오프라인으로 잡힌다 → 매 편집 E2E 불필요.
> render-정확성은 E2E 전용 → **최종 1회 게이트로 격하**.
