## S1. 설계 원칙 (문제정의 → 강제 제약)

1. **문자열 편집 금지** — 모든 `.twb` 변경은 파싱된 트리 조작 → 재직렬화. 문자열 치환 불허.
2. **2계층 검증 게이트** — 모든 산출물은 (A)XSD 구문 + (B)시맨틱 검증 통과해야 반환. 하나라도 실패 시 반환 금지.
3. **참조 자동 정합** — 편집이 참조를 깨면(rename/삭제) 의존 참조를 함께 갱신하거나, 못 하면 편집 거부.
4. **빠른 오프라인 우선, E2E는 최종 게이트** — per-edit는 정적검증만. E2E(앱실행·렌더)는 선택적 최종 1회.
5. **결정론** — 같은 입력 → 같은 출력. 무인 자동화 가능. findings 순서까지 고정(정렬 규칙 명시).
6. **심각도 배정 = 확신 기반** (v1.1 신설) — **파일이 열리지 않는다고 확신할 때만 ERROR.
   우리 지식의 공백은 WARNING.**
   - 게이트가 mandatory이므로 거짓 ERROR 1건이 멀쩡한 산출물을 막는다. 사용자는 게이트를 끄고,
     그 순간 원칙 2가 무력화된다. **거짓양성이 거짓음성보다 치명적일 수 있다.**
   - 적용 예: 함수 화이트리스트에 없는 함수 = "그 함수가 없다"가 아니라 "**우리 목록이 불완전하다**" → WARNING
   - 적용 예: calc 파싱 실패 = 문법 미커버 가능성 → WARNING(해당 calc의 하위 검사는 스킵하고 그 사실을 보고)
   - 근거: 과거 파이프라인도 독립적으로 같은 결론에 도달했다 —
     *"사람 완성본에서 오탐 0인 검사만 Tier A(게이트)로 승격"*
7. **실패는 층으로 나온다** *(v1.3 신설, 01 v2.0 §3)* — 로드 거부 → 설정 버려짐 →
   데이터 없음 → 필드 오류. **앞 층을 고치기 전에는 뒤 층이 보이지 않는다**(Tableau가 첫
   실패에서 멈춘다). 두 가지 귀결:
   - **"열린다"를 통과로 쓰지 않는다.** 층 2~4는 열리면서 틀린다 → AC9
   - **한 반복에 한 층만 고친다** ([`/defect-loop`](../.claude/commands/defect-loop.md))

## S2. 기능 요구사항 (능력 단위, 구현중립)

- **C1 안전 I/O** — `.twbx` unpack/pack (`.hyper` 바이너리 무손실 보존), `.twb` 파싱/직렬화.
- **C2 인스펙터** — 구조 모델 추출: datasources·fields·calc·sheets·dashboards·참조관계. (편집/쿼리 컨텍스트 제공)
- **C3 검증기 (2계층, 핵심 산출물)**
  - **L-A 구문**: 버전 매칭 공식 XSD 검증 (`twb_YYYY.R.0.xsd`) — 규칙 id `xsd.schema`.
  - **L-B 시맨틱** *(v1.3: 실제 규칙 id로 교체. 번호는 구현 순서일 뿐 계약이 아니다)*:

    | # | 규칙 id | 담당 | 상태 |
    |---|---|---|---|
    | ① | `calc.functions` | 함수 화이트리스트 | ✅ |
    | ② | `calc.field_refs` | 필드참조 해소 | ✅ |
    | ③ | `named.refs` | named-content 참조무결성 | ✅ |
    | ④ | *(미착수)* | 메타↔hyper 스키마 대조 | ⏸ 2차 |
    | ⑤ | *(미착수)* | connection 필수속성 | ⏸ 2차 |
    | ⑥ | `manifest.gates` | 매니페스트 게이트 | ✅ |
    | ⑦ | `ref.notation` | 표기 규약(필터·자리표시자·매개변수 한정자) | ✅ |
    | ⑧ | `calc.aggregation` | 사용자 지정 집계 정합 | ✅ |
    | ⑨ | `set.definition` | 집합 기반 필드 | ✅ |
    | ⑩ | `action.refs` | 동작(`<actions>`) 참조무결성 — 표면 9종 | ✅ |
    | ⑪ | `shelf.refs` | 선반 배치 참조무결성 (T4-a) — 표면 20여 종 | ✅ |
    | ⑫ | `calc.types` | **calc 타입 정합** | ❌ 신규 |

  - 출력 = 구조화된 findings(severity·위치·원인·수정제안) + `coverage`.
- **C4 안전 편집기** — 트리 연산: 필드 추가/수정, calc 편집, connection 변경, 색·레이아웃. 각 연산은 의존참조 자동갱신 + dangling 유발 시 거부.
- **C5 데이터 쿼리** — embedded `.hyper` 위 SQL/집계 (쿼리·분석 작업).
- **C6 E2E 게이트(선택)** — Tableau 실행→렌더→스크린샷으로 render 계층 최종확인. per-edit 아님.
- **C7 저작(build)** — 템플릿 + C4 연산으로 맨바닥 `.twb` 생성 (2차 범위).

## S3. 입출력 계약 (작업유형별)

- **편집(fix)**: `입력` = 대상 `.twbx/.twb` + 편집의도(자연어→구조화 연산). `출력` = 검증통과 산출파일 + 변경요약 + findings리포트. `불변식` = C3 2계층 통과 or 실패사유 반환(원본 무손상).
- **쿼리(query)**: `입력` = 대상파일 + 질의. `출력` = 결과셋 + 사용스키마. `불변식` = 파일 비변경(read-only).
- **저작(build)**: `입력` = 데이터소스 + 명세(시트/차트/calc). `출력` = 검증통과 신규 `.twbx`. `불변식` = C3 통과.

## S4. 검증 기준 (Acceptance Criteria)

> v1.1: MVP는 **검증기(C3)** 단독이다. 산출물을 만들지 않으므로 편집기·쿼리 기준은 측정 대상이 아니다.
> *(v1.3)* **AC 번호는 바꾸지 않는다** — 코드·테스트가 `AC2`·`AC3`·`AC5`·`AC7`을 직접 인용한다.
> 대신 S4.0에서 01 v2.0의 T1~T4에 매핑하고, 층 2~4를 담을 **AC9를 신설**한다.

### S4.0 T1~T4 ↔ AC 매핑 *(v1.3 신설)*

01 v2.0 §3의 **증상 축**(층 1~4)과 §4의 **표면 축**(T1~T4)을 AC에 붙인다.

| 목표 | 증상 층 | 무엇을 재는가 | AC |
|---|---|---|---|
| **T1** 파일이 열린다 | 층 1 (로드 거부) | 정상본 ERROR 0 · 로드거부 주입본 전량 ERROR | AC7 · AC3 · AC2 |
| **T2** 계산·매개변수 | 층 3·4 | 계산 오류 상태를 내는 파일을 검출 | **AC9** · AC2 |
| **T3** 집합·동작 | 층 1·4 | 동작은 층 1(매니페스트)·집합은 층 4 | **AC9** · AC3 |
| **T4-a** 선반 참조 | 층 2·4 | 배치 참조가 실존·표기 정합 | **AC9** |
| **T4-b** 선반 조합 | 층 4 | ⏸ **정답지 없음** — 측정 불가 (01 §7) | — |

**AC7이 모든 칸의 밑에 깔린다.** 어느 목표를 위한 규칙이든 정상본에서 ERROR를 내면 게이트가
꺼지고 나머지 전부가 무의미해진다.

### MVP(검증기) 적용 — 지금 측정한다

- **AC2 시맨틱 검출율**: L-B가 로드-실패 유발 케이스를 검출.
  - *(v1.3)* **목표 수치는 두지 않는다.** 분모(전체 실패 유형)를 모르는 채로 정한 비율은
    측정이 아니라 자기 확인이다. 대신 **절대량으로 보고한다** — "주입 레시피 N종 중 M종 차단".
    분모가 커지면(레시피 추가·표본 확대) 그 사실이 그대로 드러난다
- **AC3 무거짓통과**: C3 통과했는데 로드 실패 = 치명결함(**0 목표, 이건 비율이 아니다**).
  발견 시 해당 유형 L-B 규칙 추가 — 그 절차가 [`/defect-loop`](../.claude/commands/defect-loop.md)다.
  - 실증 사례 존재: 매니페스트 미선언 `<manual-sort>`는 XSD를 통과하고 로드 실패
    ([`06-rule-candidates.md`](./06-rule-candidates.md) R1)
- **AC7 거짓양성 0** *(v1.1 신설)*: **정상 골든셋에서 ERROR 0건.**
  - AC3(놓침)과 대칭인 반대 방향 기준. S1-6의 측정 가능한 형태
  - *(v1.3)* 정상 골든셋 = 실사용 워크북 **61개**. 확장 시 유지
  - WARNING은 허용하되 건수를 기록해 추이를 본다 (경고 인플레이션 방지)
- **AC8 `.hyper` 무손실** *(v1.2 신설)*: `unpack → pack` 라운드트립에서 `.hyper` 엔트리가
  **바이트 단위로 동일**해야 한다.
  - S1의 무손실 원칙에 측정 기준이 없어 "지켰다"를 확인할 방법이 없었다
  - **등가성이 아니라 동일성**으로 고정한다 — 재압축·재인코딩이 한 번만 끼어도 추출 데이터가
    조용히 달라지고, 그 시점에는 원인을 추적할 수 없다
  - MVP는 read-only라 pack 경로를 쓰지 않지만, C4 편집기가 들어오는 순간 필요해진다
- **AC9 빨간 느낌표 0** *(v1.3 신설)*: **층 1만이 아니라 층 2~4도 게이트가 본다.**
  - 기존 AC2·AC3는 "로드 실패"만을 실패로 셌다. 그 정의로는 **열리는데 필터가 사라진 파일,
    데이터가 안 나오는 파일, 필드가 빨간 파일이 전부 통과**다 — 사용자에게는 실패인데도
  - 측정: 층 2~4를 내는 것으로 **라벨된** 파일에 대해 규칙이 최소 1건의 finding을 낸다.
    실측 근거가 있는 4층 사례가 이미 있다 ([`05-xsd-spike.md`](./05-xsd-spike.md) F5-b~F5-e)
  - ⚠️ **ERROR가 아니라 finding이다.** 층 2~4는 파일이 열리므로 S1-6에 따라 WARNING이다.
    AC9는 "게이트가 막았는가"가 아니라 "**게이트가 말했는가**"를 잰다
  - 층 1(AC3)과 대비: 층 1은 **막는다**, 층 2~4는 **말한다**. 승격은 라벨 확보 후(`TODO.md` L2)
- **AC5 속도**: `twb_validate`가 E2E(앱기동·렌더)보다 빠름.
  - *(v1.3)* **목표 배수는 두지 않는다.** E2E baseline 실측이 사용자 배치에 묶여 있고,
    그것 때문에 프로젝트가 멈출 이유가 없다. 대신 **절대 시간을 회귀로 잰다** —
    파일당 검증 시간을 기록하고 유의미하게 느려지면 그때 본다

### 후순위 능력 적용 — MVP에서는 측정 불가

- **AC1 무에러**: 골든셋에서 **산출물** 100% Tableau 로드 성공. → C4 편집기/C7 저작 도입 후.
- **AC4 참조무결성**: 의도적 dangling 주입 → **C4가** 거부 또는 자동수정. → C4 도입 후.
  - 단 "주입된 dangling을 C3가 **검출**하는가"는 AC2로 지금 측정한다
- **AC6 read-only 안전**: **쿼리 작업이** 원본 바이트 비변경. → C5 도입 후.
  - MVP는 read-only 전용이라 자동 충족. 회귀 방지용으로만 유지

## S5. 비기능 요구사항

- **속도**: 정적검증 per-edit 목표 수초 내. E2E는 최종 1회로 격리.
- **버전대응** *(v1.1 수정)*: **`source-build`** ↔ XSD 자동 매칭(`2026.1.1` → `twb_2026.1.0.xsd`), 미지원 버전 명시 경고.
  - v1.0은 `<workbook version>`(`26.1`)을 키로 삼았으나 **실측 결과 틀렸다** — Tableau 2026.1이 만든
    파일도 `version='18.1'`(최소 호환 버전)로 저장된다 ([`05-xsd-spike.md`](./05-xsd-spike.md) F4)
  - `version`/`original-version`은 로더 문법 판정(매니페스트 게이트)에 쓴다
- **범위한계 명시**: live DB connection·`processContents=skip`·render 계층은 "오프라인 미검증" 경고 표기(조용히 통과 금지).
  - *(v1.2)* 이 요구에 **계약을 부여한다** — 리포트는 `findings`와 별도로 `coverage`를 낸다.
    `findings`가 비었다는 사실만으로는 "검사했고 문제없음"과 "검사하지 못했음"이 구분되지
    않기 때문이다. `passed`는 "검사한 범위에서 ERROR 없음"이고, "전부 검사했음"은 별개 값이다
- **원본 보존**: 편집 실패 시 원본 무손상, 항상 재현 가능. MVP는 read-only이므로 입력 파일 무변경.
- **입력 오류 처리** *(v1.1 신설 / v1.2 소유자 확정)*: 파일 없음·손상 ZIP·`.twb` 아님 등은
  예외를 던지지 않고 **ERROR finding으로 반환**한다. 게이트 판정 경로를 단일화해 호출자가
  분기를 따로 만들지 않게 한다.
  - *(v1.2)* **소유자는 엔진이다.** 이 판정은 모델 생성 전에 나므로 규칙에 맡기면
    "컨텍스트를 못 만들어 실패한 상황을 컨텍스트 받는 규칙이 판정하는" 순환이 된다
  - 입력에서 멈추면 나머지 규칙을 전부 `skipped`로 기록한다 — 침묵은 통과로 읽힌다
- **신뢰할 수 없는 입력 방어** *(v1.2 신설)*: 입력은 **AI가 생성했거나 출처를 모르는 파일**이다.
  XXE·엔티티 폭탄·zip slip·zip bomb를 파서/해제 단계에서 차단한다. 상한은 실측 대비 수십
